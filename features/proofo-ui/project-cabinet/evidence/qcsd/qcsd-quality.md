## Условие QCSQ-01 — сохранение вставки изображения из буфера

**HIGH / structural / STATIC, Direct.** `apps/web/src/app/dashboard/[slug]/platform-form.tsx:64-75,108-119` устанавливает изображение через paste на форме, включая screenshot-only вариант, и явно предлагает Ctrl+V; `:77-96` отправляет его как `screenshot`, а `:64-65,133-136` требует текст только для URL без снимка. Это самостоятельный существующий способ ручного переноса, а не OCR. `05_architecture.md:14,16` обещает сохранение PlatformForm и его state machine при новом controller и переключении, но `06_implementation_plan.md:13,29-33` конкретизирует screenshot-only и upload errors, не задавая проверку clipboard paste и его сохранности при переключении. Один выбор файла не докажет Ctrl+V; общая ссылка на сохранение компонента не задаёт oracle для этой критичной операции при смене composition.

**Требование исправления:** в подготовленной архитектуре/FR привязать существующий paste к FR-303 и обязательной проверке плана: ordinary UI получает синтетическое изображение через paste, показывает вложение, сохраняет выбранный снимок при переключении способов, отправляет именно этот снимок в существующий endpoint, после успешной отправки и reload показывает pending item с provenance. Для screenshot-only не требуются имя и текст; при предсказуемом 503 до записи ошибка видна и insert отсутствует; при сетевой ошибке исход может быть неизвестен, ложный success отсутствует, а выбранный снимок остаётся доступен для retry. Сценарий URL+text и существующий выбор файла остаются отдельно; имитацию OS clipboard при ограничении браузера нужно явно обозначить и дополнить проверкой доступной ветки. Эту проверку добавлять в план и выполнять позднее; здесь она не запускалась.
