# Архитектура project cabinet

Статус: L design rework по 13 actual QCSD origins; независимая проверка исправлений, design approval / K1/K2/native admission pending. Закрытие условий не заявлено.

## Data flow
1. Ordinary request `/dashboard/[slug]` → currentAccountId. Нет session → existing login redirect с encoded next.
2. `readOwnedProjectCabinet(accountId, slug)` → одна withAccount transaction: active project + branding; testimonials; widget_installs. Missing/foreign/inactive → null → notFound. Errors не подменяются empty data.
3. Page применяет existing isPaid/tierSummary, buildProjectUrls, allowlisted delivery notice. Берёт полный непустой строковый branding.name без mutation stored JSON, иначе slug. Создаёт `ProjectCabinetModel`.
4. Stateless `ProjectCabinetView` компонует shell/header/steps/sections, явные capability slots. Existing client modules обрабатывают реальные inputs/mutations; server loader не переносится в client.
5. `project-cabinet.css` scoped `.proofo-project` оформляет всю composition; globals/overview/branding/public unchanged.

## Component contracts
`ProjectCabinetView({ model, intake, reviews, sharing, billing, accountStatus, password })`: model содержит реальные display strings/URLs/notice/step labels и explicit product palette. ReactNode slots — конкретные existing production components. Pure view не содержит fetch, auth override, query/env fixture flags или copied cabinet.js.
`ProjectCabinetIntake({slug})`: две mounted панели manual/CSV с tabs. Switching меняет hidden/inert, не key/unmount; File, raw fields и CSV state живут в текущих components. Не добавлять parser/OCR/link fetch.
`ChangePassword` владеет show/cancel/busy; точный pre-submit/in-flight контракт ниже. Существующие endpoint payloads сохраняются.
`ImportForm/PlatformForm/ModerationList/BillingBlock/N3Status/ShareCta` сохраняют API/payload/server semantics; client state намеренно уточняется для CSV preview binding, draft retention, synchronization и focus. Backend API route/library modifications не планируются.

## Runtime/rollback — конкретная граница, не sandbox всей ОС
Новый `scripts/run-project-cabinet-qa.mjs` — единственная точка project QA. Он повторно использует `assertBrandingCollectQaConfig/buildBrandingCollectQaEnv` только как чтение/allowlist helpers; режим existing runner e2e НЕ вызывается (тот запускает branding suite). До spawn проверяет exact127.0.0.1 PG33186/database proofwall_ui_test, app33187, S3synthetic33188, foreignhost33189; никаких localhost/альтернативных loopback ports/production env. Проверяет private env ownership/mode и hash code-owned guard/target paths без symlink. Runner является единственным владельцем lock: root запускает его без внешнего flock; уже удерживаемый root lock сначала освобождается после завершения собственного lifecycle, а не наследуется через непроверенный bypass. Существующий `flock -n` держит `.secrets/branding-qe-runtime.lock` от preflight до stop/wait всех дочерних процессов и финального evidence; занятый lock → отказ, чужие процессы не останавливать. PG разрешён уже существующий dedicated QA; свободность остальных трёх портов проверяется до их запуска.
Code-owned modes: `guard-check`, `e2e`, `mutation`, `all`; e2e запускает только `node --test tools/visual/project-cabinet.e2e.test.mjs`, mutation — только `node apps/web/tests/project-cabinet-mutation.mjs`, all последовательно оба. Никаких произвольных file/command args. Receipt каждого child: exact realpath+SHA/suite mode, PID, exit/signal, four endpoint roles, guard version/ack и deny counts (без URL query/секретов); отсутствие/чужой suite/неполный teardown = failure.
`tools/visual/project-cabinet-node-egress-guard.mjs` предзагружается через absolute `--import` в app, тесты и каждый разрешённый Node child/worker до application imports. Закрытый allowlist TCP endpoints127.0.0.1:33186/33187/33188/33189; guard перехватывает net.Socket.connect (включая pg/undici), tls.connect, http/https/http2 request/connect и DNS до resolution; dgram/UDP и Unix outbound sockets запрещены. `syncBuiltinESMExports` синхронизирует patched builtins. Любой отсутствующий endpoint/guard ack, unsupported address form или попытка сменить policy → отказ. Node child_process/worker_threads ограничены exact code-owned Node entrypoints, с обязательным guard propagation; arbitrary exec/shell/curl/native helper запрещены. Единственный non-Node child — закреплённый Playwright Chromium launcher с проверенным executable hash/owned profile и отключёнными background updates/network features; его application traffic наблюдается отдельно ниже.
`tools/visual/project-cabinet-browser-egress.mjs` до page creation подключает context routing, routeWebSocket, request/requestfailed observer, serviceWorkers=block; разрешены только перечисленные app/S3/foreign HTTP origins и внутренние data/blob для synthetic media. Любой иной HTTP(S)/WS(S), popup/new context без guard или remote image/navigation/fetch — abort с deny record; не продолжать redirect к запрещённому origin. Test Node APIRequestContext также под Node socket guard. Chromium browser-internal/native OS traffic этим не доказан; его disabling flags не являются полным packet firewall. Это точная гарантия контролируемых Node JS transports/children и browser-context application requests, НЕ произвольных native syscalls, уже запущенных процессов или всей машины. Неиспользуемые transports нельзя считать проверенными: новый транспорт/негарантированное наследование guard блокирует соответствующий QA scenario до расширения наблюдения. Никаких real providers/credentials в QA.
`apps/web/tests/project-cabinet-qa-runtime.test.mjs`: `project QA runner refuses wrong ports lock and suite` — bad port/occupied flock/unknown target/guard absent до app spawn. `project QA boundary records and refuses synthetic egress` — реальные попытки Node fetch/http/net/tls/DNS, guarded Node child/worker, browser fetch/navigation/WebSocket к `provider-sentinel.invalid` и запрещённому локальному sentinel33190; refusal до DNS/connect, локальный sentinel получает0connections, audit содержитtransport+process+blocked destination class и counter. Email/payment/STT/storage intent покрываются sentinel transports, не настоящими endpoints. Expected probe denies выделены отдельным режимом; любой deny в ordinary suite делает scenario и итоговый exit ненулевыми, не просто warning. Probe failure/отсутствие ack/refusal evidence = fail-closed. Missing keys/config guard сами по себе egress proof не являются.
QA app не получает real mail/payment/STT settings. Checkout/N3 responses локальные transport fixtures, не provider integration. Существующий deployed artifact/HTTPS и production untouched. Rollback — revert feature source commit, schema unchanged; missing runtime/gate → BLOCKED.

## Client lifecycle и наблюдаемые границы
**Refresh выбран явный, через полную повторную загрузку текущего route; автоматического router.refresh после intake нет.** После успешного platform/CSV commit форма сообщает фактический результат и предлагает «Обновить отзывы»; рядом явно написано, что перезагрузка обновляет список/счётчики и очищает незавершённые черновики. До этой границы imported item не рисуется фиктивно, список соответствует последнему load. Это сознательный bounded UX, не real-time обещание. Данные не обещаются сохранёнными после reload. Steps остаются навигационными ссылками без галочек completion. Pending badge принадлежит ModerationList и вычисляется из текущего displayed items; после подтверждённой moderation меняются item+badge вместе, а failure/409 не меняет их. Install/ShareCta пересчитываются при явном полном reload; #show содержит «Обновить статус установки» с тем же предупреждением о drafts. Просмотр snippet не создаёт install.
При получении реально изменившихся server props список remount по serverSnapshotRevision (стабильная fingerprint всех выбранных item/display fields + slug), чтобы useState(initial) не оставался stale. Одинаковая revision сохраняет local state; входящие изменённые props — документированная новая server authority. На одном slug remount касается списка, не intake panels; navigation к другому slug remount всего cabinet и его drafts. Автоматического фонового refresh/race с mutation нет. Если пользователь всё же уходит/перезагружает во время запроса, серверная операция не объявляется отменённой; следующий GET восстанавливает истинное состояние. Oracle `project cabinet refresh reconciles items counts and installs` проверяет import success→до/после explicit reload, moderation item+badge, persisted install→ShareCta после reload, same/new initial props и не сброшенные соседние drafts до reload.
**Manual draft:** сохраняются сам File/bytes, name/type/size, источник paste или file, URL, platform, name, role, text при manual→CSV→manual и при400/429/503/network. Paste использует существующий form onPaste; screenshot-only разрешает пустые name/text. Test отдельно вставляет synthetic clipboard image (при OS limitations dispatch ClipboardEvent+DataTransfer с явной маркировкой) и отдельно выбирает file; сравнивает hash bytes фактически отправленного multipart screenshot после round-trip/retry, а не только filename. Предсказуемый503 до записи →0insert; потерянный ответ после server commit → исход неизвестен, нет false success/автоматического retry, сообщение предлагает проверить список перед ручным повтором (platform API не обещает idempotency). Success очищает только manual draft; CSV draft остаётся. Oracles `project cabinet preserves pasted and selected screenshots across methods and retries`, `project cabinet preserves all intake draft fields on recoverable failure`.
**CSV preview binding:** exact snapshot `{csv, mapping:{name,text,role}}` и generation сохраняется с accepted/rejected/sample. Любое изменение bytes CSV/выбранного файла/mapping инвалидирует preview+done немедленно, оставляет draft и disabled commit; новый успешный preview нужен снова. Пока reading file/preview/commit pending, соответствующие file/mapping/submit controls заблокированы; generation check отвергает запоздалый read/response. Commit отправляет именно captured successful preview snapshot, не новые current values. Switching panels ничего не инвалидирует; reload не сохраняет. Неуспешный preview не оставляет prior valid preview. Failed commit не стирает draft; definite400/429/503 оставляет прежний valid snapshot для explicit retry только пока inputs unchanged; network unknown outcome сообщает неопределённость, не автоматический успех/повтор. Success очищает preview и только CSV draft. Разрешено это исправление client state при прежнем endpoint/API. Oracle `project cabinet binds CSV commit to the successful preview`: preview→mapping change/новый CSV→disabled commit→new preview→payload exactly equals displayed snapshot; negative stale-preview and stale-response mutations красные.

## Keyboard, fields, busy и focus
Выбраны tabs (соответствуют proposal): Tab входит в единственный selected tab(tabIndex0); Left/Right переключают и фокусируют с wrap, Home/End first/last, aria-selected/controls/labelledby связаны; next Tab идёт в активный panel tabindex0 и затем controls. Hidden/inert inactive panel исключён из tab order/AX, остаётся mounted. После ошибки не переключать tab автоматически. `project cabinet keyboard tabs preserve drafts and focus` выполняет последовательности реальными keyboard events, без page.focus как замены user navigation.
Manual screenshot/URL/text/name/role/platform, CSV file/mapping и password current/new/repeat имеют уникальные id+label. Hint обязательности: screenshot ИЛИ URL+text, имя/текст необязательны при screenshot; CSV требует file и корректные indices; все password fields обязательны. Field error → aria-invalid+aria-describedby к видимому error; form error summary role=alert/tabindex=-1 содержит ссылки на поля, focus summary после submit validation; Enter по ссылке переводит к полю. API error без известного field остаётся общей alert, не выдумывать ошибочное поле. Ошибка не уничтожает исправляемый ввод.
Pending: aria-busy на операции, видимый текст «Отправка/Проверка/Импорт/Сохранение…», disabled affected controls для одного captured request; статус role=status/aria-live=polite существует до ответа. Error result → alert и разумный focus summary; success → status focus только после пользовательской submit, не на background N3 poll. При moderation pending disable actions данного item; success сохраняет карточку и фокусирует первую доступную action той же карточки (либо её status, если actions нет); error/409 сохраняет карточку/state, фокус остаётся на исходном enabled action, alert связан через describedby. При pending не steal focus с другого tab. `project cabinet fields announce validation busy errors and retry` проверяет DOM relationships + Playwright ARIA snapshot/role-name дерево при manual400/503, CSV preview/commit, moderation409 и password mismatch, без опоры только на цвет.
Password lifecycle: открыть → current input focus; cancel ДО submit очищает значения/errors, закрывает, focus возвращается на opener, POST0. ПОСЛЕ submit поля/submit/cancel disabled, busy объясняет ожидание; Cancel/Escape не abort и не обещает rollback. Форма не закрывается до результата. Success показывает фактический ответ, очищает secrets и сохраняет reissued cookie; error сохраняет форму для correction. Network timeout говорит «Результат неизвестен; проверьте вход», а не «отменено». `project cabinet password cancel respects in-flight mutation` задерживает реальный local POST, пытается cancel клавиатурой/мышью, проверяет success/error и old-cookie rejection/current-cookie access. `project cabinet moderation and password retain keyboard focus` проверяет success/failure/card action replacement и pre-submit cancel; document.activeElement не body.
Отдельная ручная AT-приёмка будущей test copy: keyboard-only + настоящий screen reader, synthetic inputs, пройти manual validation/upload pending/error/retry, CSV preview/commit, moderation state, password mismatch/cancel. Записать AT/browser/version и что услышано; отсутствие AT = unverified, не pass. Automated ARIA snapshot не заменяет это наблюдение.

## Отказы чтения и ordinary HTTP
`readOwnedProjectCabinet` null ТОЛЬКО если successful project SELECT не вернул active owned row; query reject project/testimonials/widget_installs пробрасывается, transaction rollback, partial model не возвращается. Inherited `dashboard/error.tsx` показывает generic «Не удалось загрузить кабинет» и retry. Для ordinary HTTP: nonstreamed500 либо Next streamed200 с реальным error boundary допустимы;404/успешный empty/partial cabinet при DB failure недопустимы. Не обещаем HTTP500 после отправки headers. Повторный запрос/reset+router.refresh после восстановления DB перечитывает все3SELECT; synthetic empty active project →200+empty, error нет. Никаких SQL/credentials/body payload в UI/log evidence.
`project cabinet read failures do not become empty or not found` в loader test и ordinary live test последовательно вызывает actual DB errors на каждом чтении через временное scoped REVOKE в dedicated QA DB (restore в finally под lock; без fault-injection route/env). Проверяет generic boundary, отсутствие успешных title/review/links/snippet и recovery после restore. Negative catch→null/empty mutant обязан падать.
`project cabinet HTTP denies anonymous foreign missing and inactive access` на обычном GET `/dashboard/<slug>`: две persisted synthetic identities A/B, named projects/sentinel review text; anonymous status307/303+login Location и decoded next равен encoded safe path; A→B/absent/Ainactive404, raw response и browser DOM не содержат уникальные name/text/URLs/snippet; A→active200 только свои данные. Strict CSP без bypass, реальная session cookie, без fixture route. SQL role/GUC oracle остаётся отдельным доказательством.
