## Acid cases

- A1: аккаунт A не видит карточки, counts, тарифы или события аккаунта B.
- A2: неизвестные wall opens/widget impressions и отказ БД не превращаются в `0`.
- A3: `tier=paid` с истёкшим/невалидным `paid_until` отображается бесплатным.
- A4: замена шрифта, margin или цвета ломает visual gate; baseline не обновляется автоматически.
- A5: один проект остаётся в overview; ноль и несколько проектов работают без выдуманного лимита.
- A6: fixture не создаёт production-маршрут, auth bypass или вход по служебному query/header.
- A7: email delivery notice, verification recovery и прямой project route остаются рабочими.

## Фактические роли и ограничения

Архитектор — `gpt-6-astra xhigh`, текущая отдельная задача координатора.
Автор кода назначается координатором (`gpt-6.1-sol high`); независимый reviewer
архитектуры — отдельная сессия другой модели (`gpt-6.1-terra xhigh`). Назначение
не означает выполненного review. QCSD и итоговый fleet организует координатор;
этот документ не выдаёт чтение протокола за запуск трёх агентов.

Владелец уже согласовал конкретный dashboard-макет и продолжение работы («да давай»)
после плана dashboard → branding → collect. GitHub CI отложен владельцем;
все обязательные проверки локальные. Production-поставка этим не разрешена.

Recall выполнен: `npm run dz -- recall "Proofwall dashboard UI реальные тарифы метрики visual baseline RLS" --project /home/proofwall --limit 3`, exit 0, 2 lexical hits.
Полные значения читаются отдельно перед применением. AQE runtime/recall и QCSD
подтверждает координатор; отсутствие сведений здесь не считается успехом.
