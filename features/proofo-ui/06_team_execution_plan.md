# Команда и алгоритм переноса Proofo UI/UX

План сообщён владельцу до начала исследования 11.11.2026. Уточнение владельца: доступ к закрытой части позже, начать с открытых экранов.

| Роль | Модель | Режим и результат |
|---|---|---|
| Координатор | gpt-6.1-sol high | Общий scope, ownership файлов, сборка доказательств |
| Исследователи | gpt-6.1-sol high | Отдельные сессии для публичного референса и reuse текущего проекта |
| UX-архитектор/планировщик | gpt-6-astra xhigh | Карта экранов, gap-анализ, спецификация и зависимости |
| Автор макета/интерфейса | gpt-6.1-sol high | Изолированный макет, затем согласованный код |
| Независимый code reviewer/QE | gpt-6-astra xhigh | Новая сессия без истории кодирования; требования → самостоятельное исследование кода/тестов |
| Проверяющий артефактов Astra | gpt-6.1-terra xhigh | Другая модель; независимая проверка архитектуры/плана |

Максимум три исполнителя плюс координатор одновременно. Разный reasoning одной модели не считается cross-model. Историю автора и его заявления об успехе не передавать reviewer как исходное доказательство. В независимый запуск передавать требования, ADR, план, версию артефакта; фактические model ID и ограничения фиксировать.

## Алгоритм

1. Read-only публичный аудит: браузерные страницы, размеры1440/390, ссылки, поля, состояния, CSS/типографика, виджеты и инструкции. Не отправлять формы референса и не обходить auth.
2. Сопоставление с Proofwall: reuse, отсутствующие возможности, данные/API и неопределённость. Главные функциональные gap — OCR и ratings. Кабинет неизвестен до доступа.
3. Локальный feature-adr по измеренному риску: router, требования/OpenSpec с FR mapping и hash, reuse, ADR/QCSD, архитектура, план, настоящие K1/K2/checkpoints. Публичная реализация предварительно L, весь продукт XL/unknown. Для L/XL расширенный fleet QE по применимому skill.
4. Конкретные desktop/mobile макеты → согласование владельца согласно AGENTS. Макет явно демонстрационный, не обещает рабочий backend.
5. Реализация законченными пользовательскими сценариями с сохранением текущего Next.js/npm workspaces, PostgreSQL, S3 и доверительных границ. Сначала общие tokens/components, затем страницы и связи с API; OCR/rating — отдельные согласованные backend-дельты.
6. Реальные unit/integration/E2E и визуальное сравнение референс/реализация при одинаковых viewport, screenshot baselines, формы/ошибки/переходы/клавиатура/overflow. Порог визуальных отличий закрепляется в плане; синтетический demo-контент не считается точным content parity.
7. Независимый cross-model QE → исправление конкретных findings → focused повторная проверка → code/spec anti-drift.
8. Тестовый VPS → ссылка/инструкция ручной приёмки → согласованная поставка того же артефакта. Основной DNS только по отдельной команде.

## Навыки и инструменты

feature-adr, frontend-design (измеренное воспроизведение референса важнее произвольного стиля), применимые QE/review протоколы. Проектный dz recall/teach, OpenSpec, Git/worktrees, rg, npm/TypeScript, Docker Compose/Caddy. Браузерные измерения и screenshots фактически выполнялись Puppeteer-core/Chromium148; E2E реализации планируется Playwright/Chromium. Недоступные интеграции не объявляются установленными.

## Что выполнено сейчас

Два read-only аудита Sol; выборочная проверка и стратегия Astra; статический макет Sol; независимый review Terra и корректирующий проход; измерения и screenshots Chromium. App UI/backend не заменены. На VPS добавлен только read-only static preview и Caddy prefix /__design/proofo/. Закрытая часть, рабочий OCR и полнота parity не заявлены.
